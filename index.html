Intención (Intensión) de una Relación

Es la descripción estructural de la relación: su nombre, los nombres de sus atributos, los dominios asociados y las restricciones de integridad. Corresponde al esquema de la tabla — no cambia con el tiempo ordinariamente.

📌 Ejemplo — Intención de CURSO
CURSO ( CodCurso: Códigos, Nombre: Nombres, NHoras: Horas, Materia: Materias )

Formato: Relación ( Atributo₁: Dominio₁, Atributo₂: Dominio₂, … Atributoₙ: Dominioₙ )

📌 Ejemplo — Intención de ESTUDIANTE
ESTUDIANTE ( Matricula PRIMARY KEY, Nombre, Apellido, Email )
Extensión de una Relación

Es el conjunto de tuplas (registros/filas) que contiene la relación en un instante determinado. Representa los datos reales almacenados. Cambia con cada operación INSERT, UPDATE o DELETE.

📌 Ejemplo — Extensión de CURSO (tabla real con datos)
CODNOMBREEXISTENCIAUBICACIÓN

Cada fila = una tupla. El número de columnas = grado. El número de filas = cardinalidad.

Grado de una relación

Número de atributos (columnas) que tiene la relación. En el ejemplo CURSO con atributos COD, NOMBRE, EXISTENCIA, UBICACIÓN → Grado = 4.

Entidad Fuerte

Es aquella que tiene existencia propia e independiente. Posee una clave primaria propia que la identifica unívocamente, sin depender de otra entidad.

Regla de traducción:

  1. Se convierte en una tabla relacional.
  2. Cada atributo simple se convierte en una columna.
  3. La clave del ER se convierte en la PRIMARY KEY.
📌 Ejemplo – Sistema Universitario
-- Entidad ER: ESTUDIANTE (Matricula, Nombre, Email) CREATE TABLE ESTUDIANTE ( Matricula VARCHAR(10) PRIMARY KEY, Nombre VARCHAR(80) NOT NULL, Email VARCHAR(120) ); -- Entidad ER: CURSO (Codigo_Curso, Nombre_Curso, NHoras) CREATE TABLE CURSO ( Codigo_Curso VARCHAR(10) PRIMARY KEY, Nombre_Curso VARCHAR(100) NOT NULL, NHoras INT );
Entidad Débil

Es aquella que no posee clave primaria propia. Su existencia depende de una entidad fuerte (entidad propietaria). Se identifica mediante una clave parcial combinada con la clave de la entidad fuerte.

Regla de traducción:

  1. Se convierte en tabla con clave parcial + PK de la entidad fuerte.
  2. La combinación de ambas forma la PRIMARY KEY de la tabla resultante.
  3. La clave foránea referencia a la entidad fuerte.
📌 Ejemplo – Factura depende de Cliente
-- Entidad fuerte: CLIENTE CREATE TABLE CLIENTE ( ID_Cliente INT PRIMARY KEY, Nombre VARCHAR(100) ); -- Entidad débil: FACTURA (clave parcial: Num_Factura) CREATE TABLE FACTURA ( ID_Cliente INT NOT NULL, Num_Factura INT NOT NULL, Fecha DATE, PRIMARY KEY (ID_Cliente, Num_Factura), FOREIGN KEY (ID_Cliente) REFERENCES CLIENTE(ID_Cliente) );
¿Cómo se reconoce en el diagrama ER?

La entidad débil se dibuja con un rectángulo de doble línea. La relación identificadora se dibuja con un rombo de doble línea.

🔵 Atributos Simples ▶

Son indivisibles. Se traducen directamente como columnas en la tabla.

-- Atributos simples de ESTUDIANTE Matricula, Nombre, Email → columnas directas
🟡 Atributos Compuestos ▶

Pueden descomponerse en sub-atributos. Se traducen expandiendo cada componente como columna separada.

-- Nombre_Completo → descomponer en componentes Nombre_Completo → Nombre, Apellido Domicilio → Calle, Numero, Ciudad -- Resultado en la tabla: ESTUDIANTE (Matricula, Nombre, Apellido, Calle, Numero, Ciudad, Email)
🔴 Atributos Multivalorados ▶

Pueden tener múltiples valores para una misma entidad. Se traducen creando una nueva tabla separada con clave foránea.

-- Teléfonos del estudiante (puede tener varios) CREATE TABLE TELEFONO ( Matricula VARCHAR(10), Telefono VARCHAR(15), PRIMARY KEY (Matricula, Telefono), FOREIGN KEY (Matricula) REFERENCES ESTUDIANTE(Matricula) );
🟢 Atributos Derivados ▶

Se calculan a partir de otros atributos. Generalmente no se almacenan en la tabla relacional; se calculan en las consultas.

-- Edad se calcula desde FechaNacimiento -- No crear columna Edad; usar función en SQL: SELECT Nombre, DATEDIFF(NOW(), FechaNacimiento)/365 AS Edad FROM PERSONA;

Diagrama ER
Relación Uno a Uno (1:1)

Una instancia de la entidad A se asocia con a lo sumo una instancia de la entidad B, y viceversa.

Regla de traducción:

La clave foránea puede colocarse en cualquiera de las dos tablas. Se prefiere colocarla en la entidad con participación total (la que siempre tiene la relación).

📌 Ejemplo — Persona y Pasaporte
Esquema ER

PERSONA ─(1:1)─ PASAPORTE

  • PERSONA (ID_Persona, Nombre)
  • PASAPORTE (Num_Pasaporte, Vencimiento)
→
Esquema Relacional
PERSONA (ID_Persona PK, Nombre) PASAPORTE (Num_Pasaporte PK, ID_Persona FK, Vencimiento)
Relación Uno a Muchos (1:N)

Una instancia de la entidad A se puede asociar con muchas instancias de B, pero cada instancia de B se asocia con a lo sumo una de A.

Regla de traducción:

La clave foránea se coloca en la tabla del lado "muchos" (lado N), referenciando la clave primaria del lado "uno".

📌 Ejemplo — Profesor dicta Cursos
Esquema ER

PROFESOR ─(1:N)─ CURSO

Un profesor dicta varios cursos, pero cada curso lo dicta un único profesor.

→
Esquema Relacional
PROFESOR (ID_Prof PK, Nombre) CURSO (Cod_Curso PK, Nombre_Curso, ID_Prof FK -- lado N )
📌 Ejemplo — Departamento y Empleados
DEPARTAMENTO (ID_Depto PK, Nombre, Presupuesto) EMPLEADO (ID_Empl PK, Nombre, Cargo, ID_Depto FK)
Relación Muchos a Muchos (N:M)

Una instancia de A puede relacionarse con muchas de B, y viceversa. Es el caso más frecuente y el más complejo de traducir.

Regla de traducción:

Se crea una tabla intermedia (puente) que contiene las claves foráneas de ambas entidades. La clave primaria de la tabla intermedia es la combinación de ambas claves foráneas.

📌 Ejemplo — Estudiante inscrito en Cursos
Esquema ER

ESTUDIANTE ─(N:M)─ CURSO

Un estudiante puede inscribirse en muchos cursos; un curso puede tener muchos estudiantes.

→
3 Tablas Resultantes
ESTUDIANTE (Matricula PK, Nombre) CURSO (Cod_Curso PK, Nombre_Curso) -- Tabla intermedia: INSCRIPCION ( Matricula FK, Cod_Curso FK, Fecha_Inscripcion, PRIMARY KEY(Matricula, Cod_Curso) )

Dominio de un Atributo

Es el conjunto de valores válidos que puede tomar un atributo en una entidad. Define el tipo de dato, rango permitido y restricciones aplicables. Todo atributo pertenece a exactamente un dominio.

Notación formal: R ( A₁:D₁, A₂:D₂, … Aₙ:Dₙ )

D_precio

Entidad: Producto
Tipo: Numérico real ≥ 0
Notación: {x | x ∈ ℝ, x ≥ 0}

CHECK (precio >= 0.00)

D_ISBN

Entidad: Libro
Tipo: Cadena de 13 dígitos únicos
Notación: alfanumérico único

ISBN CHAR(13) UNIQUE

D_duracion

Entidad: Película
Tipo: Entero positivo (minutos)
Notación: {x | x ∈ ℕ, x > 0}

CHECK (duracion > 0)

D_salario

Entidad: Empleado
Tipo: Numérico real positivo
Notación: {x | x ∈ ℝ, x > 0}

CHECK (salario > 0.00)
Superclave

Cualquier conjunto de atributos que puede identificar unívocamente una tupla. Puede contener atributos redundantes.

Clave Candidata

El menor conjunto de atributos que puede identificar unívocamente cada tupla. Puede haber varias en una tabla.

Clave Primaria (PRIMARY KEY)

La clave candidata elegida por el diseñador para identificar unívocamente cada registro. No admite valores nulos ni duplicados.

Clave Foránea (FOREIGN KEY)

Atributo(s) de una tabla que referencian la clave primaria de otra tabla. Garantizan la integridad referencial.

Clave Parcial

Atributo(s) que identifican una entidad débil dentro del contexto de su entidad propietaria. Por sí solos no son únicos globalmente.

Restricción de Integridad Referencial

Garantiza que todo valor de una clave foránea debe existir previamente en la clave primaria de la tabla referenciada. Notación: Tabla1.FK ⊆ Tabla2.PK

📌 Ejemplo — ¿Qué pasa si se viola la integridad referencial?
INSCRIPCION (con error)
MatriculaCod_CursoFechaEstado
1001MAT1012024-02-10✓ OK
9999MAT1012024-02-11✗ ERROR

⚠️ El estudiante con Matricula=9999 no existe en ESTUDIANTE → violación de integridad referencial.

📌 Ejemplo — Restricciones en SQL
-- Restricción de integridad referencial INSCRIPCION.Matricula ⊆ ESTUDIANTE.Matricula INSCRIPCION.Cod_Curso ⊆ CURSO.Cod_Curso -- En SQL DDL: FOREIGN KEY (Matricula) REFERENCES ESTUDIANTE(Matricula) ON DELETE CASCADE ON UPDATE CASCADE, FOREIGN KEY (Cod_Curso) REFERENCES CURSO(Cod_Curso)
